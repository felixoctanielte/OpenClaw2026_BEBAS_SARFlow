# SOP Guardrails

Source basis: SK KBSN 154/HM.01.04/VI/BSN-2020 public service standard, manually summarized from scanned pages 6-8.

## Intake Requirements

A SAR report should collect:
- reporter identity;
- reporter contact that can be reached;
- incident type;
- clear incident information;
- location or last known location;
- time of incident or last seen/contact;
- estimated victim count;
- victim condition if known.

## Administrative Flow

Use this sequence:

1. Receive the report.
2. Record the report.
3. Verify and search for additional information.
4. Prepare incident briefing for officers.
5. Log operational timeline.
6. Draft report after updates are available.

## Verification Labels

Use these labels per field:
- `confirmed`: explicitly stated by reporter/officer.
- `inferred`: likely from context, needs confirmation.
- `missing`: not yet provided.
- `conflict`: inconsistent information appears.

## Hard Boundaries

Never output final operational commands. Use wording like:
- "Rekomendasi verifikasi administratif"
- "Perlu konfirmasi petugas"
- "Data belum terverifikasi"

Avoid wording like:
- "Tim harus evakuasi melalui..."
- "Korban pasti berada di..."
- "Informasi ini boleh diumumkan..."
